# Customer password recovery

The login page includes **Forgot password or not receiving a code?** in both login modes, in English and Arabic. Customers can request an email reset code without signing in, enter the code, and choose a new password. Reset codes expire after 10 minutes, allow at most 10 failed attempts, and have resend limits. Account eligibility and delivery failures receive a neutral response.

When email is unavailable:

1. An administrator opens the customer's profile from **Students / Clients**.
2. Verify the account owner's identity through an established, trusted channel.
3. Under **Password recovery**, check **I verified the account owner's identity**, then select **Generate recovery link**.
4. Copy the link and share it privately with the verified customer, for example through the existing WhatsApp support channel.
5. The customer opens the link and chooses their password before signing in.

Links expire after 30 minutes and can be used once. Generating another link invalidates the previous link. Only the token hash is stored; the browser removes the credential fragment after opening it. Issuance is recorded in the admin audit log without the token. The reset and credential consumption occur in one database transaction, which also invalidates outstanding login and recovery codes.

Support links are restricted to active customer accounts and can only be generated by administrators. They cannot reset staff/admin accounts or unblock restricted accounts. Password reset preserves the account's login security mode: an account configured for password plus OTP will still require its second factor. Existing signed-in sessions follow the existing session policy.

No database migration or new environment variable is needed. Frontend and backend changes must both be deployed.
